# Changes to copy to the locked (kexec) headset

Changes made on the unlocked Quest 2 that still need to be brought over to the kexec setup (`pull/kexec/desk330-init.sh` + `q2boot.img`).

## Settings (files on the SteamOS root, no code change)

- `/var/lib/q2/vrscale` = `1.0` — native VR render resolution (was 0.55).
- `/var/lib/q2/panelscale` = `80` — compositor output 1536x2930, scaled to the panel by the display engine (was 65%; 100 = full size cost ~2 ms GPU more per frame and dropped frames).

## Code changes (init)

- **desk-331 – instant audio:** q2fw copies `CM710X.bin` (case kept) into `/lib/firmware`; q2audio waits for `/tmp/q2fw.vendor.done` before loading the sound modules and reloads `machine_dlkm` once if no card appears.
- **desk-332 – PC mode stays on:** in `q2usbpc`, the UDC state `suspended` (Windows USB power saving on an idle cable) no longer counts as unplugged.
- **desk-332 – root serial console:** `agetty -a root` on `ttyGS0`, so PuTTY lands in a root shell without logging in.

- **desk-333 – Meta's VR GPU power profile** (from Meta's `vendor/etc/powerhint.cfg`), set at boot next to the GPU clock: `bus_split=0`, `force_bus_on=1`, `force_clk_on=1`, `force_rail_on=1`, `idle_timer=10000`. GPU clock unchanged (525 MHz). Native: compositor GPU 10 → 8 ms/frame, dropped frames 45 → 3 of 128. Off switch: `/var/lib/q2/nometabus`.

- **desk-334 – q2kmsd real-time:** `CPUSchedulingPolicy=fifo` / `CPUSchedulingPriority=70` in `q2-kmsd.service`. At normal priority it missed page flips while Steam was busy (SteamVR presented 90/s, the panel got 40–60).
- **desk-334 – stock 587 MHz GPU level (device tree, not code):** in the boot image's **kona v2.1** DTB, bin 0's GPU levels `805, 670` were replaced with bin 1's stock `670, 587` (same DTB, 8 bytes changed). The init then pins the GPU at 587 MHz (highest level ≤ 587). The kexec kernel takes its device tree from a different place (live DT / its own build), so this needs redoing there.

- **desk-334 – unattended test switches (off by default):** `q2_test=1` on the kernel command line (or `/var/lib/q2/autopc` + `/var/lib/q2/stayawake`) = PC mode starts by itself 60 s after boot, and SteamVR keeps rendering off-face.
- **desk-343/344 – Bluetooth works (QCA6390):**
  - kernel: `patches/q2-bt-hci-qca-ldisc.patch` (hci_qca + btqca): no NULL serdev oops in line-discipline mode; QCA6390 version reply (15 bytes, command-complete style) and 2-byte TLV acks accepted; NVM baud rate written to byte 1 (newer-SoC layout; the file's default 0x11 = 3.2 Mbit/s vs the host's 3 Mbit/s); NVM sleep bits cleared and no in-band sleep for the QCA6390 (it stays awake); HCI reset straight after the NVM. Do NOT retry the reset inside the kernel (desk-346: froze the headset until the watchdog rebooted it into fastboot).
  - init (`q2bt`), desk-348:
    - **Wi-Fi pauses during Bluetooth setup** (`nmcli radio wifi off` + `ip link set wlan0 down`, restored after). The QCA6390 is one chip for both; with Wi-Fi up the chip never answers the HCI reset after the NVM (A/B: on fail, off ok, on fail).
    - writes the real address into the NVM's BD_ADDR tag (2) before the chip loads it, from Meta's `persist/bluetooth/.bt_nv.bin` (tag 1, 6 bytes, same byte order). (desk-343 used `btmgmt public-addr`, which needs a power off/on that left the chip silent.)
    - retries setup with a power cycle, up to 5 tries (the first try after power-on often times out on the patch download).
  - The kexec kernel needs the same Bluetooth patch, and its init the same `q2bt` changes.
- **desk-350 – right-eye blocks fixed:** compositor `TU_DEBUG` default `nobin,hiprio,flushall`. The blocks / black "ghost laser" in one eye are a GPU cache bug in Turnip on KGSL (stale data in the second eye's pass); flushing after every draw removes them, at no GPU cost (dashboard 7.2 → 6.2 ms). Proven with panel captures (`q2vrshot`, reads the scanout framebuffer). LRZ, multipos, UBWC, tiling and overlay quality made no difference.
- **desk-350 – Steam's VR panels not forced to the headset rate** (`steamMatchesHMDFramerate` false by default; `/var/lib/q2/dashmatch` = 1 to turn it on): compositor with a game on the theater screen 12.1 → 11.3 ms.

- **desk-352 – boot loop fixed:** the init must have LF line endings (a CRLF init from git autocrlf boot-looped desk-348…351); `.gitattributes` now forces `eol=lf` for `image/src/**`, `patches/**`, `kernel/**`, scripts.
- **desk-353 – overlay quality back to low** (`OVLQ` default 1): high made the dashboard ~12 ms and dropped half the frames.
- **desk-354msm/355msm/356 – GPU on the mainline drm/msm driver (q2msm) instead of KGSL** (branch `q2msm`, details in `docs/DRM-MSM-PORT.md`):
  - kernel cmdline `initcall_blacklist=kgsl_3d_init` (KGSL never probes; replaces `kgsl.force_lazy_gpumem=2` to fit the cmdline field).
  - `kernel/q2msm` = mainline 5.10 drm/msm GPU part as an out-of-tree module (`build-q2msm` workflow), shipped as `/usr/lib/q2/q2msm.ko` and loaded by q2desktop right after `q2fw` (before the GL probe), only when KGSL is blacklisted.
  - GPU stack `/opt/q2gpu` (build-q2gpu) and `/opt/q2gl` (build-mesa-gl) now also build **freedreno** (native Adreno GL, `msm_dri.so`): gamescope-vr's Xwayland gets GBM/glamor/GLX, so Steam starts in VR again (with only Turnip it died on `glXChooseVisual failed`).
  - desk-356: Steam's UI in VR at 90 fps (gamescope `-r 90`; `/var/lib/q2/steamvrhz` overrides).
  - Result on the headset: q2msm from boot, GPU test PASS, runtime suspend/resume, desktop GL = zink on Turnip/msm, SteamVR 90 Hz (compositor GPU ~8 ms, 0 dropped), Steam binds into SteamVR, fastfetch "Qualcomm Turnip Adreno (TM) 650".
  - For the kexec headset: q2msm has to be built against the kexec kernel and the blacklist added to its command line; KGSL's runtime unbind is not a substitute (its teardown leaves the GPU RSC asleep - q2msm now wakes it, but a clean boot without KGSL is the tested path).
- **desk-357 – head pose age to SteamVR:** `driver_q2hmd` sets `poseTimeOffset` = -(age of the q2metapose sample, 0.5–5 ms) so SteamVR predicts from the pose's real time (`Q2VR_POSEAGE=0` = old). No visible change on its own.
- **desk-357 – unattended tests can't wedge the headset** (`q2_test=1` only): `q2-testguard` sets `panic_on_oops=1` (oops → immediate reboot, `panic=-1`) and reboots via sysrq if a task stays in D state for 90 s.
- **Boot image size:** layered images (one ramdisk layer per change) reached the boot partition limit (`Volume Full` at 81.9 MB). `image/tools/flatten_boot.py` merges the layers (newest file wins, hard links become copies): desk-357 ramdisk 55.9 → 38.2 MB, image 64.7 MB.
- Setting: `/var/lib/q2/photonms` = `16` (VR prediction; was 11, no visible difference).
- **desk-358 – plain `reboot` / `reboot bootloader` work again:** the ADB gadget units (`adbd-pre`, `adbd`, `adbd-post`) are masked; their teardown oopsed in `ncm_free_inst` and hung every shutdown. Testguard fix: a task counts as stuck only if it isn't scheduled at all (the first version rebooted on the display's `crtc_commit` thread, which sits in D state at every vblank).
- **desk-358 – q2msm options from files:** `/var/lib/q2/q2msmargs` (every boot) and `/var/lib/q2/q2msm_try` (next boot only, renamed to `.used` before the load, so a hang comes back on the defaults). A try boot loads `/var/lib/q2/q2msm_dev.ko` if present (driver tests without reflashing).
- **desk-359 – q2msm with working preemption** (image module = the fixed build; on the unlocked headset turned on with `/var/lib/q2/q2msmargs` = `preempt=1`, delete the file to go back to one ring). SteamVR + Steam UI: dropped frames 2 per ~80 s → 2 per ~4 min, no GPU errors in 20 min incl. a Steam restart. One unexplained 90 s GPU-fence stall (retire worker + display commit) happened once after a Steam restart and wasn't reproduced.
- **desk-360 – GPU clock fixed at 587 MHz on q2msm:** the init's clock code only wrote KGSL's sysfs, so on q2msm the GPU ran on devfreq `simple_ondemand` (305–670 MHz, ~35 changes/s, incl. the owner-added 670 level a stock headset doesn't have). Now q2desktop sets the devfreq min = max = highest level ≤ 587 MHz right after loading q2msm (`q2_gpudcvs=1`: automatic, capped at that level). Compositor GPU 7.8 → 7.4 ms/frame.
- **desk-362 – q2msm fence deadlock fixed (the "rare fence stall", which became frequent):** with preemption every ring is its own fence context, and a submit holds `struct_mutex` while it waits for another ring's fence (`msm_gem_sync_object`). In this 5.10 code the `dma_fence` was only signalled by `retire_submits` under `struct_mutex`, and the retire work ran on the ordered `msm` workqueue behind other `struct_mutex` users (`msm_gem_free_work`) → retire worker / display commit stuck 90 s → testguard reboot (several times an hour). Now `update_fences` signals the fences itself (on `system_highpri_wq`, no mutex; ring submit lists under a new `ring->submit_lock`), and only the cleanup takes the mutex (its own work item). Soak: 16 min with two Steam restarts, no stall. desk-361 (signalling moved without the list lock) oopsed on a freed submit within a minute – don't use it.
- **desk-363 – vblank lead (fewer missed refreshes = fewer doubled frames when turning):** SteamVR's compositor times each frame for a display it drives directly; here the finished image still goes through the layer's copy, the q2kmsd socket and an atomic flip (~5 ms), and presents came 8.3 ms into the 11.1 ms refresh (≈3 ms slack). `libq2vrdisplay.so` (now built by the `build-q2layer` workflow) puts its vsync ticks/timestamps `Q2VR_VBLEAD_US` ahead of the real refresh; the init passes `/var/lib/q2/vblead` (µs). Raise `/var/lib/q2/photonms` by the same amount so head prediction still targets the photon time. Settings now: `vblead` = `4000`, `photonms` = `20`. Still headset, 30 windows of 128 frames: no lead ~22 dropped, 3 ms 13, 4 ms 7.
- **desk-365 – Steam UI GPU-process restarts mostly gone + why memory ran out:** `libq2vrdisplay.so` (loaded in Steam's processes too) keeps waiting when `vkAcquireNextImageKHR` on someone else's swapchain times out (Chromium uses 2 s, then kills its GPU process); `Q2VR_ACQWAIT=0` = off, `Q2VR_ACQWAIT_S` = limit (default none - the stalls last minutes while nobody looks at Steam's panel). Left: a couple of restarts right after Steam starts. Found with the new `gemstat`: **SteamVR's compositor keeps every overlay texture it was ever handed** (497 dma-buf fds open; 1.2 GB of GPU buffers whose owners - old Steam GPU processes, gamescope, Xwayland - were long dead). Each Steam GPU-process restart leaked 60-100 MB that way, ~160 restarts a day → swapping → missed frames. Restarting SteamVR frees it (2.19 GB → 250 MB of dma-bufs).
- **Steam UI GPU-process restarts (cause, q2msm):** Steam's CEF GPU process exits with `vulkan_swap_chain.cc: vkAcquireNextImageKHR() hangs` → `Exiting GPU process because some drivers can't recover from errors` (exit 8704): Chromium's own Vulkan swapchain (`-cef-use-vulkan`) gives up when gamescope stalls (Steam start, Theater); each restart rebuilds its GPU memory. Tried without `-cef-use-vulkan` (`/var/lib/q2/novkui`): no restarts, but Xwayland then leaks ~100 MB/min of window buffers (out of memory in ~15 min) - so the switch stays on. Not a kernel/ioctl failure (the new ioctl error log stays quiet when it happens).
- q2msm debug: `cat /sys/module/q2msm/parameters/gemstat` = GPU buffer memory per allocating process (total / purgeable / active); unexpected GPU ioctl errors and nonzero fault counts are logged (`q2msm: ... failed`).
- testguard: on a stall it also logs every thread inside the GPU/display driver and a sysrq-l CPU backtrace (the lock holder keeps running, so the old report never showed it).
- ~~Setting: `/var/lib/q2/deskres` = `1920x1080`~~ withdrawn (now `deskres.off`): "no cost" was measured while the GPU still boosted to 670 MHz. At the fixed 587 MHz it cost ~20 of 128 compositor frames (frames shown twice = double images when turning the head). Back at 1280x720: ~3 of 128.
- Setting: `/var/lib/q2/steamvrhz` = `60` (Steam's UI renders at 60 fps; the compositor still shows it at the head pose 90 times a second): dropped compositor frames ~3 → ~1 of 128, because the UI's GPU submissions hold up the compositor less often (preemption is between submissions only).
- **q2msm GPU preemption (`q2msm.preempt=1`, off by default):** 4 rings by priority; the CP switches rings at the yield point after each submission (`plevel=0`). Needed on top of the first version: ring 0's save addresses at GPU start (`pstart`), the per-ring read-pointer shadow cleared at every GPU init (a stale one made an empty ring look busy and wedged the switch). Draw-call level (`plevel=1`, KGSL's default) hangs mid-frame here, even with a user state record per ring (KGSL's scratch-slot scheme); `CP_PREEMPT_ENABLE_LOCAL` / `CP_YIELD_ENABLE` are opcode errors on the a650 firmware. Stay on `plevel=0`.

Settings files also on the unlocked headset now: `/var/lib/q2/tuprio` = `0,4,8,12` (late warp, compositor, apps, background on separate KGSL rings), `/var/lib/q2/compositor_tu` = `nobin,hiprio` (tiling retested with OneShot: no gain).

Latest build: `image/out/boot_steamos_desk348.img` (and `_test` with `q2_test=1`) = desk-330 image + patched DTB (`image/out/boot334.dtb`) + one ramdisk layer: init348, the Bluetooth kernel (stay-awake build) and its Wi-Fi/audio modules (`image/out/mkclean.py` builds the clean base).
